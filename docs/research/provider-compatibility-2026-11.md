# Provider compatibility review

Reviewed public stable releases on November 14, 2026 against Navet's adapter and deployment paths. This review used release notes and source inspection.

## openHAB 5.2.4

5.2.4 is the latest stable release. It fixes myopenHAB authentication and SSE streaming. The 5.2.3 patch also fixed authentication with cloud and proxies. The 5.3 release series is at milestone stage. [5.2.4 release](https://github.com/openhab/openhab-distro/releases/tag/5.2.4) · [5.2.3 release](https://github.com/openhab/openhab-distro/releases/tag/5.2.3) · [release list](https://github.com/openhab/openhab-distro/releases)

The 5.2.2 security changes require same-origin redirects and S256 PKCE for the openHAB OAuth login flow, change how trusted networks are evaluated behind reverse proxies, and add a default-empty allowlist to the sitemap image proxy. Navet uses authenticated REST Item requests, its own optional proxy, and the openHAB `/ws` API. Those paths do not use the openHAB OAuth login or sitemap proxy. Based on those interfaces, no adapter change was identified. An installation relying on implicit trusted-network access should use explicit openHAB credentials and verify REST and realtime access behind its proxy. [5.2.2 release](https://github.com/openhab/openhab-distro/releases/tag/5.2.2#-security-fixes-and-breaking-changes) · [Navet openHAB service](../../packages/provider-openhab/src/openhab-service.ts) · [Navet openHAB proxy](../../docker/njs/openhab-proxy.js)

## Homey 13.5.3

Athom lists 13.5.3 as the latest stable version for current Homey Pro and Pro mini, Self-Hosted Server, and Homey Cloud. The release includes a security update and product fixes. The published changelogs list no change to the Web API OAuth delegation and session flow Navet uses. The public Web API also still documents the bearer-token HTTP contract and Socket.IO integration for third-party clients. Issue #328 concerns Navet dropping existing zone relationships and merging labels, so the firmware update does not resolve it. [Pro and Pro mini changelog](https://homey.app/en-us/wiki/homey-pro-firmware-changelog/) · [Self-Hosted Server changelog](https://homey.app/en-us/wiki/homey-shs-changelog/) · [Cloud changelog](https://homey.app/en-us/wiki/homey-cloud-changelog/) · [Web API specification](https://api.developer.homey.app/http-and-socket.io/http-specification) · [Navet zone types](../../packages/provider-homey/src/homey-types.ts) · [Navet Homey authentication](../../docker/njs/homey-store.js)

## Home Assistant 2026.11.1

The 2026.11 compatibility changes use the entity naming context and child-device area inheritance in the Home Assistant adapter, and prefer the reported `temperature_unit` for thermostat values. The custom panel install guide uses Marketplace for 2026.11 and newer. Home Assistant keeps existing entity IDs and migrates HACS installations into Marketplace. [Stable release](https://github.com/home-assistant/core/releases/tag/2026.11.1) · [Entity naming](https://www.home-assistant.io/blog/2026/11/03/naming-things-in-home-assistant/) · [Device registry](https://contributors.home-assistant.io/blog/2026/08/19/device-registry-websocket-api-changes/) · [Climate units](https://contributors.home-assistant.io/blog/2026/10/08/climate-native-temperature/) · [Marketplace](https://contributors.home-assistant.io/marketplace/how-it-works/)

The stricter OAuth client check can reject standalone sign-in when Navet is opened via a public, global IPv6, or Tailscale IP and its origin differs from Home Assistant's. Navet derives the client ID from its browser-facing origin. The troubleshooting guide covers hostnames and supported proxy configuration. Live Marketplace installation, thermostat confirmation, and sign-in through the actual deployment route remain unverified.
