# Marketing media capture

The files in this directory are captured from Navet's provider-free demo runtime. Use the capture
script instead of manually recreating cards or editing product screenshots.

## Refresh everything

From the repository root:

```bash
pnpm marketing:capture
```

The command starts the local demo on `127.0.0.1:4178`, opens it with Playwright, captures the
defined screenshots and walkthroughs, converts screenshot sources to JPG, WebP, and AVIF, then
stops the demo.

Capture only one media type:

```bash
pnpm marketing:capture:screenshots
pnpm marketing:capture:videos
```

To capture an already-running local or deployed demo:

```bash
pnpm marketing:capture -- --base-url=http://127.0.0.1:5173
NAVET_CAPTURE_BASE_URL=https://demo.navet.app pnpm marketing:capture
```

To refresh selected screenshots without replacing the rest of the set, pass one name or a
comma-separated list:

```bash
pnpm marketing:capture:screenshots -- --scenario=navet-ipad-landscape-home
```

Do not point the script at a real household dashboard. Marketing media must contain demo data only.

## Screenshot set

The canonical scenarios live in `scripts/capture-marketing-media.mjs`:

- Home: 1448x1012 tablet landscape, 1024x1366 portrait tablet, and a 390x766
  safe-area-aware phone viewport exported at 2x
- Energy: 1536x1024 landscape
- Climate: 1536x1024 landscape
- Security: 1536x1024 landscape
- Lights: 1536x1024 landscape and 430x932 phone
- Media: 1366x1024 iPad Pro landscape and 430x932 iPhone portrait
- Household and Routines: 1536x1024 landscape

Each screenshot is written to `screenshots/` with matching `.jpg`, `.webp`, and `.avif` filenames.
Website code should prefer AVIF and WebP sources with JPG as the fallback.

## Public docs reuse

The screenshot command automatically copies the scenarios listed in `DOCS_SCREENSHOTS` in
`scripts/capture-marketing-media.mjs` into `assets/public/docs/how-to/`. This includes the Home,
Lights, Climate, Media, Security, Household, and Routines views, settings, and Add Card states.
The Energy guide uses the **Day** capture; the Lights guide uses the landscape capture.
Refreshing a selected scenario also updates its public docs copies.

Dialog and focused task captures live in `scripts/capture-docs-media.mjs`. Start the local demo
and Storybook in separate terminals, then capture their public-safe fixtures:

```bash
pnpm demo:dev
pnpm --filter @navet/storybook run storybook
pnpm docs:capture
```

The defaults are demo port 5173 and Storybook port 6006. If either server chooses another port,
pass `--demo-base-url=http://127.0.0.1:5174` or `--base-url=http://127.0.0.1:6007` after `--`.
Capture one task or a comma-separated list with its path, without the extension:

```bash
pnpm docs:capture -- --scenario=wall-displays/screensaver-settings
```

Each scenario names its exact story ID or demo route and the actions that produce the documented
state. For example, dashboard creation uses
`pages-dashboard-multiple-dashboards-create-dialog--phone-sheet` on its content step; resizing uses
`components-shared-card-size-selector--phone-sheet`; alarm confirmation uses
`cards-entity-alarm-panel--all-supported-modes` with **Emergency Trigger** open. The script disables
story interaction autoplay so tests cannot advance the captured state. A failed scenario leaves
its previous files intact and makes the command fail.

Use screenshots that demonstrate the surrounding instructions. Do not reuse a generic Home view
as proof that a card was added, a pack was applied, or a room was reorganized. A phone viewport
capture illustrates the layout; it does not establish that PWA installation works on a device.
The Navet Cards preview under `assets/public/cards-preview/` belongs to the separate Navet Cards
product and is not generated by the Navet app capture commands.

## Walkthrough set

Playwright records:

- `campaigns/live-product-tutorials/recordings/final/navet-dashboard-walkthrough.webm`
  - Home, Lights, Media Library, media players and screens, Energy, Security, then Home
- `campaigns/live-product-tutorials/recordings/final/navet-mobile-home-walkthrough.webm`
  - a paced scroll through the mobile Home dashboard

The walkthroughs are silent source recordings. Keep them as WebM for the web, or make an MP4 copy
for editing and wider distribution:

```bash
ffmpeg \
  -i assets/reference/marketing/campaigns/live-product-tutorials/recordings/final/navet-dashboard-walkthrough.webm \
  -c:v libx264 -crf 18 -preset slow -pix_fmt yuv420p -movflags +faststart \
  assets/reference/marketing/campaigns/live-product-tutorials/recordings/final/navet-dashboard-walkthrough.mp4
```

## Review checklist

Before committing refreshed media:

1. Have the maintainer manually compare the screenshots with the current Navet UI; agents do not
   perform visual comparisons unless explicitly requested.
2. Check that demo fixtures contain no private URLs, credentials, entity names, or household data.
3. Have the maintainer review landscape, portrait, and phone crops for clipped controls or
   unintended overlays.
4. If walkthroughs changed, play both through once and check that every transition settles before
   the next one.
5. Run `git diff --check`, `pnpm docs:build`, and `pnpm website:build` for affected consumers.

When a dashboard route or capture story changes, update the scenario or walkthrough steps in the
capture script first, then regenerate the media.
